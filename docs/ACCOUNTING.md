# MBusiness: единое рабочее пространство

Пользовательский бренд — MBusiness. Основные разделы учёта импортированы из
собственного репозитория `milaniumkz/M-uchet`, branch `codex/import-source-backend`;
точная ревизия в `modules/muchet/SOURCE.json`. Исходный репозиторий не изменён.
Технические имена пакета/каталога сохранены для совместимости импортов.

Веб-сборка использует только `lib/main_server.dart`, REST workspace и его
зависимости. Старые Firebase-адаптеры сохранены как исходный материал и не входят
в активную сборку; Firebase и Google sign-in не подключаются. Шрифты и CanvasKit
обслуживаются локально. Меню «Интеграция → 1Kaspi» отделяет банковские инструменты
от основного учёта и допускает добавление следующих интеграций.

## Вход и данные

Владелец входит через MBusiness один раз. Авторизованный `/accounting-api/*`
проксирует запросы на loopback API. Сервер выдаёт краткоживущую сессию учётного
модуля через закрытый bridge endpoint с секретом; этот токен не попадает в браузер.
В новой отдельной PostgreSQL создаются собственные UUID компании/владельца.
Нативные login/register/password и создание дополнительных компаний закрыты
на gateway. Учётный backend самостоятельно проверяет членство и права компании.
Выход из MBusiness закрывает доступ к gateway, даже пока внутренняя сессия жива.

Перенесён независимый REST-модуль, а не старая production-база. Старые аккаунты,
Firebase config, секреты, документы и подключения не переносились. Приглашения
дополнительных пользователей требуют объединения моделей доступа; их создание
пока явно блокируется, чтобы не выдавать неработающие приглашения. Работа
владельца, справочники, проекты и остальные независимые учётные разделы доступны.
Ограничения налогов/регламентированного учёта исходного модуля сохраняются:
это внутренний учёт, не обещание юридически утверждённой отчётности.

## Изолированный сервер

Только ресурсы MBusiness:

- Docker `mbusiness-accounting-db`, PostgreSQL 17, порт `127.0.0.1:55439`;
- PostgreSQL app role `mbusiness_app` без superuser; отдельная БД;
- `mbusiness-accounting.service`, API `127.0.0.1:3191`;
- данные, файлы и закрытые env в `/srv/mbusiness/shared/accounting`;
- web build в собственном release, `/accounting/` с проверкой сессии;
- дамп перед миграциями в `/srv/mbusiness/backups/accounting-*.dump`.

Скрипт проверяет метку владения, имя контейнера и loopback binding. Ограничены
CPU/RAM. Он не перезапускает Docker daemon, MTaxi или общий Nginx.
Секреты генерируются на сервере, не помещаются в Git и не печатаются в Actions.

## Проверки

`npm test` — MBusiness, gateway и платежи; `npm run test:http` — HTTP simulator.
В `modules/muchet/server`: `npm ci`, `DATABASE_URL=... npm test`;
`DATABASE_URL=... APP_ENV=test node --test test/mbusiness-bridge.test.js`.
Flutter 3.35.6: `flutter pub get --enforce-lockfile`,
`flutter test test/rest_api_client_test.dart`, затем сборка из workflow.
`DATABASE_URL=... APP_ENV=test npm run test:browser` — настоящий browser flow
с временными схемами PostgreSQL, локальной сборкой и sandbox, без банка.

Печатные формы экспортируются в PDF локально с локальными шрифтами. Пользователь
открывает или печатает скачанный PDF средствами своего браузера; загрузка
стороннего PDF viewer и inline-script печати не требуются.

## Последовательная настройка новой компании

После регистрации открывается «Настройка компании». Она также доступна в
основном меню и по `/#setup`. Прогресс и черновики хранятся в отдельной PostgreSQL
для своей компании и сохраняются между входами/перезапусками.

Порядок: компания и налоги → реквизиты → денежные счета → проекты → склады →
контрагенты → товары/услуги → начальные остатки. Обязателен основной профиль:
юридическое название, ИП/ТОО, налоговый режим и явный выбор статуса НДС.
БИН/ИИН и реквизиты можно заполнить позже. Остальные шаги допускают пропуск;
отложенные шаги остаются в списке и доступны для повторного открытия.

Формы сохраняют данные через существующие учётные команды с idempotency key и
контролем версии настроек. Уже созданные записи распознаются, повторное создание
не требуется. Остатки вносятся через специализированные разделы денег/склада/
долгов. Финальный шаг сохраняет дату начала и отметку проверки, не создавая
проводок и не изменяя остатки. Дата в мастере не передатирует документы.

Внутренние endpoints: `GET/POST /v1/companies/:id/setup`,
`PATCH /v1/companies/:id/setup/draft`. Авторизация и `organization.write`
обязательны. Сервер проверяет порядок, реальные сохранённые записи, версии и
обязательный профиль; пропустить обязательный шаг или закончить раньше нельзя.
Этот мастер не требует Kaspi, оплаты тарифа или API-ключа для начала учёта.
