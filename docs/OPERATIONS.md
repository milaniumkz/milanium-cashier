# Эксплуатация MVP

## Запуск на сервере

API, Appium и Android — три самостоятельных процесса. Supervisor следит за каждым. Примеры `ops/*.service` рассчитаны на Linux и каталог `/opt/android-cashier`; замените пути, пользователя и расположение Node/Appium под свою установку. Выполняйте CLI обслуживания под тем же сервисным пользователем.

Для внешнего доступа настройте HTTPS reverse proxy к `127.0.0.1:3080`. В `.env` укажите точный origin без пути:

```dotenv
NODE_ENV=production
PUBLIC_BASE_URL=https://cashier.your-domain.example
HOST=127.0.0.1
DRIVER_MODE=android
```

`NODE_ENV=production` запрещает sandbox и HTTP public URL. Порты Appium/ADB/эмуляторов наружу не публикуются. Админ-панель управляет банковской сессией, поэтому доступ к ней выдаётся только операторам. В этой версии используется один пароль администратора и cookie с HttpOnly, SameSite=Strict; в production — Secure. Пароль создаётся `npm run init`, не используйте общий пароль для разных установок.

Reverse proxy не должен записывать тела запросов, Authorization, Cookie и полные одноразовые ссылки оплаты. Настройте собственный TLS/сетевой доступ и ограничение запросов; встроенный лимит логина за reverse proxy общий для его IP.

## Состояния и восстановление

| Ситуация | Поведение и действие оператора |
| --- | --- |
| Вход истёк | `requires_auth`; открыть Android, войти, проверить кассира, безопасно повторить задачу до отправки |
| Неверная компания | `WRONG_MERCHANT`; отправка блокируется; проверить аккаунт и `account_label` |
| Обрыв до фиксации отправки | `failed`; допускается явная кнопка повтора |
| Обрыв после начала отправки | `unknown`; автоматического повторного счёта нет |
| ID счёта уже получен | Worker сверяет существующую операцию |
| ID не получен | В истории приложения найти исходную операцию и указать ID через «Запросить сверку» |
| ID/сумма/валюта/reference не совпали | `PAYMENT_EVIDENCE_MISMATCH`; заказ не подтверждается |
| Android открыт вручную | Компания `maintenance`, очередь приостановлена до «Проверить кассира и запустить» |
| Перезапуск/пауза при активном QR | QR скрывается, операция сверяется, замена автоматически не создаётся |
| Webhook не доставлен | Повторы с увеличением задержки; после 12 попыток ручной повтор из панели |

Если после неопределённой отправки в истории нельзя доказательно найти операцию, оставьте её на ручном разборе. В этой версии нет кнопки «принудительно оплачено» или автоматического снятия блокировки без подтверждения. Не создавайте другой order_id для обхода сверки.

В один момент worker управляет только одним действием на устройстве. Активный QR также останавливает проверки других счетов этой компании, чтобы не увести приложение с QR-экрана. Для большого потока QR это существенное ограничение; расширение пула касс потребует отдельных учётных записей/устройств и маршрутизации.

## Перезапуск и резервное копирование

Останавливайте API штатно, оставляя до 65 секунд на завершение. При грубом завершении durable marker определяет, можно ли повторить задачу. Защита от дублей консервативна: неопределённый результат требует сверки и может остановить очередь.

`DATA_DIR/server.lock` ограничивает работу одним процессом API. CLI `create`, `bind`, `install`, `inspect`, `connect` требует остановленного API. Если авария оставила lock, сначала убедитесь, что ни хостовый, ни контейнерный API не работает с этой БД, и только затем удалите stale lock. PID хоста и контейнера может отличаться.

Для согласованной резервной копии остановите API и Android, сохраните весь `DATA_DIR`, `.env` и приватную live-конфигурацию. Храните резервные копии зашифрованными. Не заменяйте `ENCRYPTION_KEY` без миграции: старые телефоны, привязки устройств и секреты webhook станут нечитаемыми. API-ключи в БД хранятся как хеш; восстановить исходный ключ нельзя, можно выпустить новый.

Данные AVD и авторизация приложения находятся на диске Android и не шифруются ключом SQLite. Нужны права сервисного пользователя и шифрование хоста/резервных копий. Не клонируйте авторизованный AVD между разными компаниями.

## Наблюдение

Следите за `unknown`, `requires_auth`, очередями, недоставленными событиями и доступностью Appium/устройств. `/healthz` проверяет только API. `GET /v1/capabilities` показывает конфигурацию и состояние подключения, но не гарантирует, что приложение доступно прямо сейчас. Возвраты/отмена счёта и автоматическая очистка старых данных пока не реализованы.
