# Подключение настоящего Kaspi Pay на Mac

Этот комплект подготавливает локальный сервис и помогает получить реальные экраны
приложения для настройки робота. **Готового проверенного коннектора Kaspi пока нет.**
Первый необходимый результат — открыть приложение под кассиром на Android и
получить структуру главного экрана, формы удалённой оплаты и истории.

## 1. Подготовьте Android

Если Kaspi Pay уже запущен на Android, оставьте его открытым. Физический телефон
подключите к Mac по USB, включите «Для разработчиков → Отладка по USB» и подтвердите
подключение на телефоне.

Если нужен экземпляр приложения внутри системы, создайте Android-эмулятор:

1. Установите [Android Studio](https://developer.android.com/studio).
2. В SDK Manager установите Android SDK Platform-Tools, Android Emulator,
   Android SDK Command-line Tools (latest), платформу Android 15 / API 35 и её Build-Tools.
3. В Device Manager создайте телефон с отметкой Google Play. Для Apple Silicon
   используйте образ `arm64-v8a`, для Intel — `x86_64`; выберите Google Play / API 35.
   Если такой образ недоступен для выбранного профиля, используйте доступный
   совместимый профиль/образ с Google Play, не подменяя архитектуру.
4. Запустите Android и установите оригинальный Kaspi Pay из Google Play, если он там
   доступен для этой среды. Войдите в аккаунт кассира самостоятельно.

Вход на Mac в браузере не заменяет вход кассира внутри этого Android.
Совместимость Kaspi Pay с выбранным эмулятором ещё не проверена. Если приложение
не запускается или отказывает во входе, используйте физический Android; сообщите,
на каком экране оно остановилось. Защиту приложения скрипты не изменяют.

## 2. Подготовьте проект

Нужны Node.js 24+ и npm 10+. Установщик Node: https://nodejs.org/en/download.

Распакуйте архив, откройте Terminal в папке `milanium-cashier` и выполните:

```bash
bash setup-mac.sh
```

Команда устанавливает зависимости сервиса, создаёт `.env.mac`, отдельную базу
`data-mac` и конфигурацию `config/android.mac.json`, проверяет инструменты.
При первом запуске выводится пароль локального кабинета. Повторный запуск
сохраняет существующие настройки. Старый `.env` симулятора не используется.

Если SDK установлен не в `~/Library/Android/sdk`, перед командой задайте
`ANDROID_HOME` с действительным путём. Скрипт использует JDK из стандартной
установки Android Studio; при нестандартной установке задайте `JAVA_HOME`.
Проверка на Apple Silicon учитывает запуск Terminal под Rosetta при выборе
архитектуры образа для команды `android create`.

## 3. Соберите экраны для настройки

Appium на этом шаге ещё не нужен. Остановите локальный сервер, если он запущен.

```bash
npm run mac -- capture
```

Скрипт предложит выбрать устройство и вручную открыть:

- главный экран кассира;
- форму удалённой оплаты, не отправляя счёт;
- историю операций;
- детали своей существующей операции, если она есть.

После каждого экрана нажимайте Enter; `s` пропускает экран. Не создавайте
дополнительный платёж только ради диагностики.

Результат — `diagnostics/kaspi-ui-<время>.json`. Проверьте его и приложите в чат.
Файл содержит идентификаторы элементов, классы, координаты и известные стандартные
подписи. Другие тексты скрываются. Скриншоты, токены, файлы приложения, серийный
номер устройства и сырая XML-разметка в отчёт не включаются. Структура сначала
создаётся во временном файле Android, который скрипт пытается удалить после чтения.

Если приложение не отдаёт доступную разметку, команда сообщит об этом. Пришлите
текст ошибки и снимок нужного экрана с закрытыми личными данными. Сбор диагностики
не означает, что автоматизацию можно будет выполнить: это определяется по реальному UI.

Команда сохраняет наблюдаемые package/activity в `android.mac.json`, но не заполняет
селекторы предположениями и не включает реальные счета. Чтобы подготовить отправку,
ещё нужно подтвердить путь к кнопке отправки и способ однозначной привязки статуса
к банковской операции. Один номер телефона и сумма такой привязкой не считаются.

## 4. Локальный кабинет и экран Android

Эти шаги можно выполнять после получения первого отчёта. Установите Appium 3:

```bash
npm install -g appium@3
appium driver install uiautomator2
```

Если драйвер уже установлен, повторная установка не нужна. Версии установленного
Appium и драйвера зафиксируйте у себя после проверки совместимости. Установщик
Mac не меняет их автоматически. Официальные требования и установка:

- https://appium.io/docs/en/latest/quickstart/requirements/
- https://appium.io/docs/en/latest/quickstart/uiauto2-driver/
- https://github.com/appium/appium-uiautomator2-driver#requirements

Запустите кабинет:

```bash
npm run mac -- start
```

Откройте http://127.0.0.1:3080 и войдите с паролем из `.env.mac` (ADMIN_PASSWORD).
Создайте свою компанию; в поле кабинета кассира укажите то название/идентификатор,
которое действительно видно в Kaspi Pay. Сохраните выданные API-ключи у себя.
Остановите сервер через Ctrl+C и привяжите Android:

```bash
npm run mac -- bind
```

Выберите компанию и устройство. Скрипт не заменяет уже привязанный другой Android.
Запустите Appium в отдельном Terminal из той же папки:

```bash
npm run mac -- appium
```

В первом окне снова выполните `npm run mac -- start`. После шага capture у компании
можно открыть экран Android в кабинете. Входите и подтверждайте SMS внутри
приложения. Пока коннектор не проверен, кнопка возобновления робота не включит
отправку. Appium слушает только 127.0.0.1.

## 5. Настройка и первый настоящий счёт

После анализа отчёта требуется адаптировать и проверить `android.mac.json` и при
необходимости драйвер по [CONNECTOR.md](CONNECTOR.md). Текущий универсальный
контракт может не соответствовать конкретной версии Kaspi Pay. Не включайте
`verified` и `LIVE_AUTOMATION_ENABLED` просто для устранения сообщения об ошибке.

Когда сценарии действительно настроены и проверены: остановите API, укажите
`LIVE_AUTOMATION_ENABLED=true` в `.env.mac` и выполните:

```bash
npm run mac -- connect UUID_КОМПАНИИ
npm run mac -- start
```

Первый счёт создайте на свой номер плательщика с явно выбранной вами суммой и
подтвердите оплату сами. Сверьте ID, сумму, продавца и статус в Kaspi Pay и сервисе.
QR и платёжная ссылка подключаются отдельно после подтверждения их работы.

## Локальный адрес и опубликованный стенд

Этот путь работает на вашем Mac. Предыдущий опубликованный тестовый сайт не
подключается к Android автоматически. Для первого удалённого счёта по телефону
достаточно локального кабинета: счёт, если интеграция заработает, получит телефон
покупателя. Страница `127.0.0.1` на другом устройстве не откроется.
Публичная страница оплаты и постоянный доступ из приложений потребуют отдельного
размещения backend или защищённого подключения к работающему Mac.

## Проверка комплекта

В среде разработки проверены JavaScript, синтаксис bash и автоматические тесты
парсинга устройств/экранов и скрытия текстов. Реальная macOS, Appium, Android и
Kaspi Pay в этой среде недоступны; запуск на вашем Mac и банковский цикл ещё
предстоит проверить.
