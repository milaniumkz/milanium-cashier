# Обновления исходного Kaspi-коннектора

Workflow `.github/workflows/kaspi-upstream.yml` проверяет ветку main репозитория
`tapter-dev/kaspi-pos-automation` ежедневно в 05:00 UTC (10:00 UTC+5), вручную
через Actions и при изменении конфигурации монитора в основной ветке.
GitHub может запускать scheduled jobs с задержкой. Расписание действует после
попадания файла workflow в default branch, не просто в feature-ветку.

Версия, на основе которой сделана адаптация, хранится в
`.github/kaspi-upstream.json`: reviewed_commit. При новых коммитах workflow
создаёт или обновляет одну GitHub Issue с сравнением и списком проверок.
Для того же upstream SHA повторных уведомлений нет. Закрытую пользователем
задачу монитор не откроет заново до появления нового upstream-коммита.

Чтобы получать уведомления, включите Watch → Custom → Issues в вашем
репозитории MBusiness или Subscribe у созданной задачи. Если хотите адресное
упоминание, задайте repository variable UPSTREAM_NOTIFY_LOGIN с вашим GitHub
логином. Учётная запись пользователя в этом чате не подписывается автоматически.
Никакие Slack/email сообщения workflow самостоятельно не отправляет.

Монитор работает независимо от чата. Ассистент не работает в фоне и не получает
автоматические сообщения в этот чат. При продолжении задачи можно прочитать
созданную issue и перенести изменения после проверки.

Автоматического pull/merge или deployment upstream-кода нет: наша версия
адаптирована под изоляцию компаний, защищённые сессии и надёжную очередь.
После анализа и проверок обновите reviewed_commit в отдельном изменении.
Если проверенный commit совпадает с текущим upstream, старая открытая задача
автоматически закрывается. Если источник недоступен или API GitHub отклоняет
запрос, workflow сообщает ошибку запуска; это не означает отсутствие обновлений.

Workflow имеет только contents:read и issues:write. Ему не передаются SSH-пароль,
банковские сессии или production secrets. Если Issues отключены в репозитории,
их нужно включить в GitHub Settings.
