# Проверка поставки

Проверено 24 сентября 2026 в среде Node.js 24.19.0.

## Выполнено

- `npm run check`: синтаксис всех JavaScript-файлов сервера, панели, CLI, примеров и тестов.
- `npm test`: 29 автоматических тестов. API-авторизация, изоляция компаний, шифрование, идемпотентность, очередь, сбой до/после отправки, восстановление, webhook и защита адресов доставки.
- Android-драйвер проверен с **имитатором Appium**, включая точные поля, переключение состояний, декодирование QR, резервирование устройства, неверную компанию, отсутствие снимка, паузу и ручной режим. Используются искусственные селекторы тестового приложения; это не проверка Kaspi Pay.
- `npm run test:http`: полный sandbox-цикл через настоящий локальный HTTP — вход оператора, компания, счёт, worker, PNG QR, имитация оплаты, подтверждённый статус и повтор исходного API-запроса.
- `npm audit --omit=dev`: на момент проверки не обнаружено известных уязвимостей в установленных зависимостях. Это результат проверки реестра, не полная экспертиза безопасности.

## Не проверено в этой среде

- Установка и запуск реального Kaspi Pay: Android SDK, устройство/KVM и APK не предоставлены.
- Настоящие селекторы и банковские сценарии; доступность QR на заданную сумму, reference и статусов.
- Вход кассира, SMS, платежи, возвраты, банк/плательщик; банковские операции не выполнялись.
- Визуальная работа панели в браузере и на Android-экране. HTML/JS выдаются по HTTP, но интерактивная визуальная проверка здесь недоступна.
- Docker, systemd, TLS на вашем хосте, нагрузка, долговременная работа и обновления приложения.

Критерий готовности к реальным заказам — успешная проверка на вашем установленном приложении по `CONNECTOR.md`, включая неоднозначную отправку и последующую сверку. До этого держите реальные операции выключенными.
