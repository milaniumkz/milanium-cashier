# Каналы, CRM, AI и публикации MBusiness

Реализация: Node/Fastify, SQLite основного сервиса. Учёт/склад остаются в отдельном
PostgreSQL; интеграция AI с ним использует только фиксированные доменные маршруты.
MTaxi не изменяется. Пользовательские экраны: `/\#social`, `/\#inbox`, `/\#crm`,
`/\#publishing`, `/\#ai`. Инструкция: `/help/social`.

## Что подключает оператор платформы один раз

Защищённая форма `/operator/social` требует пароль оператора, не пароль компании.
Meta: отдельные Facebook App ID/Secret и Instagram App ID/Secret, Graph version,
Configuration ID Facebook Login for Business, Webhook URL/Verify Token и OAuth URI.
WhatsApp — Embedded Signup **v4**: прежние v2/v3 выведены из поддержки 15.10.2026.
Для сторонних бизнесов нужен подходящий статус Tech Provider/Partner либо Solution
Partner, разрешения, Live mode и App Review. Подписки: WhatsApp `messages` и
`account_update` в Dashboard; Instagram messages/postbacks/seen. События account_update
пока не меняют бизнес-состояние автоматически: отладка через Dashboard оператора.

VK/OK: зарегистрированные внешние приложения с серверным OAuth code flow и правами
групп/публикаций/фото. OK дополнительно требует Application Public Key. В VK адаптер
использует `oauth.vk.com/authorize` и API 5.199; доступность этого потока для конкретного
приложения и разрешения `wall` оператор проверяет в VK. Не подменять недоступное
разрешение пользовательским паролем или автоматизацией браузера.

OpenAI: центральный ключ, идентификатор модели с Responses+Structured Outputs,
официальные цены за миллион токенов, курс KZT/USD. Ключи шифруются AES-GCM с AAD
провайдера/компании, не отдаются клиентам и не логируются. Перед включением нужен
реальный платный тест с проверкой usage и стоимости.

Реквизиты оператора предоставлены; публичные контакты и страницы /privacy и
/data-deletion настраиваются отдельно от API-ключей. ИИН/БИН не возвращается публичным
API контактов. Реальные приложения/ключи пока не предоставлены; эти зависимости
нельзя отметить как выполненные.
Площадки могут отклонить текущий origin с портом8443; при этом нужен отдельный
HTTPS origin443 с доверенным сертификатом, без изменения проекта MTaxi.
Telegram поддерживает webhook8443, но сертификат и внешняя доступность тоже обязательны.

## Что делает клиент

Владелец MBusiness нажимает вход Facebook/Instagram/VK/OK и предоставляет доступ
своему аккаунту. Клиенту не нужно регистрировать собственное приложение разработчика.
OAuth state одноразовый, 10 минут, привязан к владельцу, компании и cookie сессии.
WhatsApp business code обменивается только сервером; выбранный номер проверяется
через WABA и debug_token/app_id. Подписка WABA/Instagram выполняется сервером.
Новый номер Cloud API может требовать регистрации с PIN; есть отдельная форма.
Для Coexistence регистрация номера этим методом не выполняется. Метод оплаты Meta
клиент добавляет в WhatsApp Manager самостоятельно.

Telegram подключается токеном бота от @BotFather, не паролем личного аккаунта.
Настраивается отдельный secret_token webhook; один бот — один webhook. Только
личные обращения к боту; группы и история личного аккаунта не импортируются.
Для TikTok личных сообщений нужен отдельный партнёрский доступ Business Messaging;
пока коннектор не включён, UI явно показывает недоступность. Ads API его не заменяет.

## Сообщения и CRM

Meta webhook проверяется HMAC-SHA256 по исходным байтам до JSON parsing, Telegram —
constant-time проверкой secret header. События дедуплицируются; создаются диалог,
клиент и новая сделка. Медиа пока только уведомление, бинарные вложения не импортируются.
WhatsApp/Instagram: консервативное окно 24 часа. Шаблоны WhatsApp вне окна ещё не
реализованы; нельзя отправить обычный текст обходным способом. Opt-out останавливает
все исходящие сообщения. Доставка исходящего текста не считается оплатой заказа.

Очередь `queued → sending → sent/delivered/read | failed | unknown` устойчива к
перезапуску. `sending` после сбоя становится unknown, без слепого повтора. Для
unknown нужна ручная сверка в исходном приложении; интерфейс повторной отправки
специально не добавлен. Изменение роли/отключение сотрудника проверяется при отправке.

CRM: контакты, фиксированная воронка, ответственные, задачи/сроки и общий inbox.
Версии сделок защищают от потерянных изменений. Пользователь не может назначить
сотрудника чужой фирмы. Изменение этапа вручную не создаёт выручку или оплату.
Пока нет произвольной настройки этапов, экспорта CRM и слияния дубликатов контактов.

## AI-продавец

Компания выбирает подключения, правила/FAQ, склад, дневной лимит и разрешение на
оформление заказов. Автоматизация по умолчанию выключена. После включения обрабатываются
только новые обращения, а не вся история. Инференс оплачивается с баланса услуг.
Модель возвращает ограниченное действие reply/quote/handoff, без HTTP/SQL/кода.

Предложение рассчитывается сервером по реальным ценам, НДС и запасу выбранного склада.
Модель не передаёт свои цены в заказ. После успешно отправленного предложения клиент
должен написать «Подтверждаю заказ». Сервер повторно проверяет цену/наличие, создаёт
заказ и резерв, затем ссылку существующего Kaspi-механизма с устойчивыми ключами.
Если сумма имеет тиыны, текущий коннектор целых KZT требует менеджера. Предложение
действует30 минут. Пока подбор ограничен первой страницей100 товаров выбранного склада.

Только фактический paid банковского invoice переводит связанную сделку в won.
Сотруднику создаётся задача на выдачу/доставку/фискализацию. AI не создаёт проводку
оплаты заказа без банковского документа и не выполняет отгрузку. Платёж и заказ
связаны в ai_turns, а документы на фактическую выдачу оформляет сотрудник.

Ручной ответ приостанавливает AI в диалоге и отменяет его ожидающие ответы.
Владелец может возобновить диалог. Оператор может вручную сверить неизвестный расход AI по подтверждению провайдера; без подтверждения резерв не освобождается. Нет средств/ошибка/неизвестный результат/конфликт —
задача менеджеру. Автоматические повторные касания, WhatsApp templates, работа с
вложениями, отдельные квоты сотрудников, полноценный AI-SMM Meta/TikTok и рекламные
кампании ещё не реализованы. Подключение AI само по себе рекламу не запускает.

## Публикации VK/OK

Только группы с подтверждёнными правами публикации; права повторно проверяются при
выполнении задания. OAuth, выбор групп, JPEG/PNG/WebP до3МБ, текст, даты/таймзона,
отмена ожидающих заданий и результаты. До10 групп/30 дат, до300 ожидающих заданий
на компанию. Не менее6 часов между постами, до3 за скользящие24ч, тот же материал
не чаще1 раза в7 дней. Подтверждаются права на материал; выводятся рекомендации.

Публикуются посты на стене группы, не массовые личные сообщения. Неизвестный результат
останавливает следующие задания группы до сверки. Владелец может вручную зафиксировать проверенный ID поста или подтвердить отсутствие публикации и отменить задание. Автоматической повторной отправки неизвестной публикации нет; подтверждение и основание сохраняются в аудите.
VK wall.post получает стабильный guid, OK mediatopic.post — GROUP_THEME. Картинки
загружаются на проверенные домены upload API; произвольные URL сервера не принимаются.

## Проверки и фактические ограничения

Автоматические тесты покрывают подписи, OAuth, изоляцию компаний, роли, дубли, окно
сообщений, opt-out, очередь, резервы/usage/стоимость, подтверждённое пополнение,
предложение/заказ/paid, handoff, права групп, антиспам и расписание. Браузерные проверки:
кабинет/мобильный экран, CRM контакт/сделка/задача, сообщение, расписание и платный AI-тест.
Внешние API в них имитируются. Настоящие Meta/VK/OK/OpenAI/Telegram и реальные
получатели этим не проверялись. Нельзя объявлять внешний канал боевым до собственного
теста владельца с его аккаунтом и полученными правами.
