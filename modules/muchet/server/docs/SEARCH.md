# Общий поиск фирмы

`GET /v1/companies/:companyId/search?q=...&limit=20`, от2 до160символов; limit1–50. Поиск охватывает текущую фирму независимо от выбранного проекта. Возвращает ограниченный набор `items` и `hasMore`: если совпадений много, нужно уточнить запрос. Это не точный общий счётчик результатов.

Поддержаны проекты, счета/акты услуг, товарные продажи, клиенты/поставщики, услуги/товары/склады, сотрудники, основные средства и начальные долги. Документы ищутся по номеру и сохранённому имени контрагента; сотрудники — по имени, ИИН и должности; каталоги — по имени и идентификатору. `%`, `_` и обратная косая черта в запросе обрабатываются буквально. Поиск не изменяет документы и не создаёт проводок.

Проверка членства и прав выполняется на сервере для каждой категории. Кадровая категория требует employees.read; ИИН не включается в краткий результат. Для перехода к сводке проекта нужны projects.read и reports.read; для товарной продажи orders.read и catalog.read. Для начального долга требуется debts.read; поиск доступен по сохранённому имени, примечанию и точному id. Остальные категории требуют соответствующего права чтения. Результаты чужой фирмы исключены. Перед открытием карточка запрашивается через обычный защищённый API; действуют её прежние права редактирования.

В клиенте кнопка «Поиск по фирме» открывает поиск с задержкой ввода, очисткой, Enter и переходом в настоящую карточку. Устаревший сетевой ответ не заменяет результат нового запроса. Длинные имена фирмы/проекта в переключателях не расширяют мобильный экран.

Production-логгер исключает query-string и не записывает тела запросов/заголовки сессии. При внутренних ошибках журнал содержит requestId, тип и код ошибки; строка SQL/детали записи не выводятся. Проверено отдельной инъекцией ошибки с приватным содержимым.
