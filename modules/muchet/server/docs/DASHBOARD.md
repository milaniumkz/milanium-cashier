# Главная и мобильный обзор

GET `/v1/companies/:companyId/dashboard`: reports.read + accounting.read + wallets.read. Единый REPEATABLE READ снимок. Параметры scope=ACCOUNTING/MANAGEMENT (включая записи BOTH), projectId или unassigned. Дата — календарный день в часовом поясе фирмы. Будущие проводки не входят в текущие денежные остатки.

money: денежные остатки, долги покупателей, долги поставщикам, полученные и выданные авансы. Основа — текущие сбалансированные строки журнала, включая исправления/обратные записи. Для проекта денежная величина означает накопленное изменение денег, отнесённое к проекту, и может быть отрицательной; отдельного физического счёта проекта она не создаёт.

Кроме семантических счетов источников учитываются исследованные точные коды справочника2026: деньги1010–1080, покупатели1210/2110, поставщики3310/4110, полученные авансы3510/4410, выданные1710/2910. Код1610 в этом справочнике — растения; он не относится к авансам. Оценочный резерв1090 не уменьшает фактический денежный остаток этой оперативной сводки. Ограниченные средства1060 входят в денежные остатки, поэтому сводка не является проверкой доступного банковского лимита. Это классификация внутреннего отчёта, а не утверждённая полная учётная политика, официальный баланс или автоматическая классификация произвольных субсчетов. Версия справочника возвращается в numericReferenceVersion.

chart содержит шесть месяцев с opening/closing. За текущий месяц closing рассчитан на дату фирмы; за прошлые — на конец месяца. Начальное сальдо включает записи до начала шести месяцев. Последний closing согласуется с money.cash. Внутренние переводы не меняют итог; исправления и отмены учитываются через фактический журнал. График показывает остатки, поддерживает отрицательные значения проекта и не выдаёт историю сторнирований за новые банковские поступления. Все суммы сервера NUMERIC/BigInt с проверкой диапазона API. Преобразование в double применяется только при рисовании пикселей графика.

Последние документы включают доступные счета/акты услуг и товарные продажи. Задачи: незавершённый документ выбранного проекта/контура, строки выписки без сопоставления (общие для фирмы в выбранном контуре), открытая налоговая задача с вручную подтверждённым сроком на сегодня или ранее (общая для фирмы). Категории возвращаются только с соответствующими правами чтения. Отменённые налоговые задачи не показываются. Никакие образцы цифр/контрагентов из макета не добавляются в рабочую БД.

D‑01: три показателя, график остатков, задачи и последние документы. Действия открывают настоящее основание, банковские операции и конкретную налоговую задачу. Создание услуг/товарной продажи наследует выбранные проект, контур и дату фирмы. Список услуг теперь имеет явный отбор контура; редактор услуги позволяет его выбрать. Выбор контрагента/услуги загружает все страницы, а не первые50 записей. Для документа1999года календарь доступен; даты редактора и отчётов охватывают допустимый сервером диапазон1–9999 без запрета по давности. Ограничения применимости налоговых правил этим не снимаются.

M‑01: отдельная мобильная компоновка — крупный денежный остаток, две компактные карточки долгов, основное действие, ближайшая задача, закреплённая нижняя навигация. Фирма/проект и вид учёта доступны на телефоне. Остальные задачи открываются списком, график и документы доступны ниже. «Ещё» и меню разделов открывают действующие разделы по правам пользователя. Точная визуальная идентичность всех38макетов по-прежнему не заявляется.

Статус налоговой задачи меняется без повторного подтверждения неизменного срока; изменение названия, даты, категории или основания сбрасывает подтверждение. Просмотр задачи без tax-calendar.write не даёт активных полей/сохранения; сервер независимо проверяет права. Неопределённые команды редакторов повторяются с прежним телом и ключом.
