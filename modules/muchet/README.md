# M-uchet

Исходный код Flutter-приложения и веб-интерфейса для дальнейшей разработки с отдельным backend. Основа: снимок main UchetSD от 6 октября 2026, commit `030efcf8c5adbcebb6348f1d5d8b155810f28ce5`. Исходный репозиторий не изменён.

## Что сохранено

- `lib/`: экраны, навигация, бизнес-логика, модели и текущие адаптеры данных.
- `assets/`, `web/`, `android/`, `ios/`, `macos/`: ресурсы и платформенные оболочки.
- `test/`, `integration_test/`: исходные проверки, которые потребуется адаптировать к новому backend.

## Что удалено и отключено

- Прежние Firebase project/client configuration, адреса рабочих сервисов и platform service-config файлы.
- Каталог прежней серверной части `firebase/`, включая Cloud Functions, административные, seed/migration/deploy скрипты и правила базы.
- GitHub Actions workflows, старые environment-подсказки и контактные примеры.
- Прежняя инициализация Firebase отключена. Основной вход открывает новый REST-интерфейс и не обращается к прежнему серверу.
- GitHub Actions в новом репозитории отключены. Деплой не выполнялся.

## Важное ограничение

Это подготовленные исходники, а не готовая автономная система. Firebase SDK, типы, запросы и авторизационные адаптеры пока остаются во многих Dart-файлах: их замена новым API является отдельной работой. Основной вход запускает REST-интерфейс: фирмы, проекты, продажи и покупки услуг, оплаты, справочники. Остальные исходные экраны ещё переносятся; простое добавление адреса сервера не завершит всю миграцию.

## Новый независимый сервер

В [`server/`](server/README.md) добавлен Node.js 24 / PostgreSQL 17 API без Firebase: сессии, права и изоляция компаний, справочники, файлы, FIFO-партии, резервирование/отгрузка/оплата заказов, двойная запись и аудит. Есть SQL-миграции, Docker Compose, Makefile, автоматические серверные тесты и проверка восстановления backup. Проверенный запуск и ограничения описаны в server/README.md. Это первый этап разработки backend; недостающие процессы и подключение клиента перечислены в [карте миграции](server/docs/FRONTEND_BACKEND_GAPS.md). Новый независимый интерфейс `lib/main_server.dart` подключён к API: вход, динамические проекты, доходы/расходы и общая сводка. Основной вход `main.dart` открывает новый REST workspace; прежние экраны ещё переносятся. Развёртывание на пользовательском сервере не выполнялось.

План подключения нового backend: [BACKEND_MIGRATION.md](BACKEND_MIGRATION.md). Модели данных сохранены в `lib/backend/schema/`.

## Среда разработки и проверки

Исходный проект использует Flutter 3.35.6 / Dart 3.9.2. Внутреннее имя Dart-пакета `uchet_s_d` сохранено для совместимости импортов. Native bundle/application ID заменены на `com.example.muchet`; перед публикацией приложения задайте свои идентификаторы.

После установки подходящей среды и адаптации backend: `flutter pub get`, `flutter analyze`, `flutter test`, `flutter build web --release --no-wasm-dry-run`. Flutter установлен в этой облачной среде: исходные тесты и web build прошли; актуальные проверки и ограничения — в [checkpoint](docs/CHECKPOINT.md). При первоначальной подготовке архива SDK отсутствовал. Выполнены статическая проверка структуры, удалённых конфигураций и сканирование импортируемых файлов.

Никакие учётные данные, пользователи, рабочие коллекции, файлы Storage, секреты GitHub или история исходного репозитория не переносились. Старые визуальные ресурсы и технические имена сохранены там, где они не являются подключением к сервису; ребрендинг не выполнялся.


## Новый интерфейс и проекты

`make bootstrap`, `make bootstrap-flutter`, `make up`, `make seed-dev` подготавливают локальную среду. `make build-workspace-web` собирает новый интерфейс. Для совместного запуска web/API: `make down`, затем `WEB_ROOT=/workspace/M-uchet/build/web make up`; открыть локальный `http://127.0.0.1:8080/`. Пароль синтетического владельца сохраняется в приватном `.runtime/synthetic-login.json`; в Git его нет. Пользовательский сервер ещё не подключён.

Проекты создаются произвольно, имеют собственные доходы/себестоимость/расходы/прибыль и сводку по фирме. Налоги относятся к фирме; общие операции выделены отдельно. Дизайн-кит: [docs/design](docs/design/README.md). Полная миграция и все экраны ещё не завершены; [текущее состояние](docs/CHECKPOINT.md).

Подготовка контейнерного запуска на собственном сервере: [deploy/README.md](deploy/README.md). Локальная изолированная проверка не является production-развёртыванием.

Начальные взаиморасчёты: раздел «Долги» с проектами, реальными оплатами, исправлениями, авансами, историей и внутренним PDF. Описание и ограничения переноса старых записей: [server/docs/DEBTS.md](server/docs/DEBTS.md).

Главная D-01/M-01 подключена к реальным данным: остатки денег, долги, история остатков за шесть месяцев, документы и задачи. Выбранные проект и вид учёта применяются к показателям и созданию документа. Подробности: [server/docs/DASHBOARD.md](server/docs/DASHBOARD.md).

Склад: сводные остатки, резервы, минимумы товаров, стоимость и CSV всего отбора; инвентаризация с черновиками, проведением, исправлением и историей. Это внутренний учёт в описанных границах: [server/docs/INVENTORY.md](server/docs/INVENTORY.md).

Денежные возвраты по услугам: возврат клиенту/от поставщика, дата фактических денег, исправление, отмена/восстановление и история с автором. В банковской выписке можно создать возврат по документу либо сопоставить уже учтённый. Стоимость услуги и НДС изменяются через акт: [модель и API](server/docs/COMMERCIAL_DOCUMENTS.md).

Товарные закупки: черновик, предоплата до поставки, проведение в FIFO и долг поставщику, НДС в стоимости/к проверке, исправления, оплаты/денежные возвраты, сверка и переход из партии к основанию. Границы пересчёта использованного запаса и физических возвратов: [товарные закупки](server/docs/PURCHASES.md).

Возврат товара поставщику оформляется отдельным документом из карточки поступления: партии, дата, исправления, отмена/восстановление, история и PDF; долг пересчитывается на дату возврата, деньги учитываются отдельно. [Описание и текущие границы](server/docs/PURCHASE_RETURNS.md).
