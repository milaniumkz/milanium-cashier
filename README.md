# Android Cashier · сервис оплаты для мобильных приложений

Самостоятельный MVP: HTTP API, кабинет оператора, очередь платежей, webhook и управление **установленным Android-приложением** через Appium / UiAutomator2. Каждой компании выделяется собственный Android Virtual Device (AVD) или физический Android. Вход кассира сохраняется внутри этого устройства.

**Статус:** backend и симулятор работают; написан Android-драйвер и панель просмотра/управления устройством. Настоящий Kaspi Pay здесь не установлен, его экраны и операции не проверены. APK и готовых селекторов Kaspi в архиве нет. Это исходники для подключения и испытаний, а не уже подключённый платёжный провайдер.

## Запуск за несколько минут

**Для подключения настоящего Android на Mac:** начните с [MAC_START.md](docs/MAC_START.md).
Выполните `bash setup-mac.sh`, затем `npm run mac -- capture`. Этот путь использует
отдельный режим Android; команды ниже относятся только к симулятору.

Нужен Node.js 24 и npm.

```bash
npm ci
npm run init
npm start
```

Откройте `http://127.0.0.1:3080`. Пароль администратора напечатает `init`; он также сохранён в локальном `.env`. Добавьте компанию и сохраните выданные API-ключ и секрет webhook. Они показываются один раз. В тестовом режиме значение «Кабинет кассира» может быть любым названием.

Создайте счёт «QR / ссылка» и откройте страницу оплаты. На тестовой странице можно имитировать оплату или отказ. **Sandbox не обращается в Kaspi и не перемещает деньги.** Android для этого режима не нужен.

## Работа в облачной среде разработки

Клонируйте репозиторий в облачную среду с Node.js 24 или новее и выполните:

```bash
npm ci
npm run init
npm run check
npm test
npm start
```

Откройте порт 3080 через приватный проброс портов вашей среды. При необходимости
задайте `HOST=0.0.0.0` и `PUBLIC_BASE_URL` с адресом проброшенного порта в `.env`.
Для Docker доступен `docker compose up --build` после `npm run init`.

`npm run init` создаёт новые `ADMIN_PASSWORD` и `ENCRYPTION_KEY` в локальном `.env`.
Храните их в менеджере секретов облачной платформы или в этом файле с правами 600;
не вставляйте значения в код, Git, задачи или логи CI. Для GitHub Actions используйте
Settings → Secrets and variables → Actions. `.env.example` содержит только шаблон.
Действующие `.env*`, базы, снимки Android и локальные конфигурации исключены из Git.
Ключ шифрования сохраняйте вместе с резервной копией базы: новый ключ не расшифрует старые данные.

В облаке сразу доступен sandbox. Для реального Android потребуется отдельно
настроенный Android-хост и доступ к Appium; банковские сессии и данные устройства
через репозиторий не переносятся. Подробности — в [ANDROID_SETUP.md](docs/ANDROID_SETUP.md).

## Как подключается мобильное приложение

Мобильное приложение обращается к вашему backend. Backend получает цену из своей базы заказов и вызывает API этого сервиса. Сервис ставит задачу в очередь и управляет приложением кассира на Android. Клиент получает страницу оплаты; ваш backend узнаёт результат через подписанный webhook или запрос статуса.

API-ключ компании хранится на backend, а не в APK / IPA / Flutter-коде. Успешное возвращение из Kaspi в ваше приложение само по себе не подтверждает оплату.

```bash
curl http://127.0.0.1:3080/v1/invoices \
  -H "Authorization: Bearer $CASHIER_API_KEY" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: order-1001-attempt-1' \
  -d '{"order_id":"1001","amount":15000,"currency":"KZT","method":"phone","customer_phone":"+77001234567"}'
```

Ответ содержит `id`, `status: queued` и `checkout_url`. Для QR используйте `method: qr` без номера. Ссылка банка появляется только после получения её из приложения/QR. `checkout_url` — страница вашего сервиса; `payment_url` — извлечённая ссылка банка, если она доступна.

## Что реализовано

- Изоляция компаний по API-ключу и отдельному Android; одинаковые устройство и порт UiAutomator2 нельзя назначить двум компаниям.
- Долговечная очередь SQLite, последовательные действия на одном устройстве, до четырёх одновременно занятых компаний.
- Отправка по телефону; получение настоящего изображения QR из приложения и декодирование ссылки, когда это позволяет UI.
- Экран Android в кабинете: нажатия, ввод в выбранное поле и кнопка «Назад». Ручной режим останавливает очередь компании. Закрытие окна не возобновляет робота.
- Сверка статуса существующей операции по идентификатору, сумме, валюте и внутреннему номеру счёта.
- Защита от повторной отправки при повторе API-запроса и при обрыве после нажатия кнопки оплаты.
- Webhook HMAC-SHA256, повторная доставка, журнал изменений и ручная сверка неопределённых операций.

## Переход на установленный Kaspi Pay

1. Подготовьте Android-хост по [ANDROID_SETUP.md](docs/ANDROID_SETUP.md).
2. Установите оригинальное приложение на отдельный Android и войдите в аккаунт кассира.
3. Проверьте, что приложение работает в выбранной среде. При несовместимости эмулятора привяжите физическое устройство.
4. Настройте UI-сценарии по [CONNECTOR.md](docs/CONNECTOR.md), используя реальные экраны и версию приложения.
5. Подключите кассира и проведите контролируемую проверку полного цикла с вашим тестовым заказом.

**Наличие эмулятора не гарантирует совместимость банковского приложения.** Если приложение закрывает UI для автоматизации/снимков, или нет надёжной связи заказа с банковской операцией, соответствующий способ оплаты остаётся недоступным. Код не обходит проверки устройства, SMS, PIN или защиту снимков экрана.

## Ограничения этой версии

- Один процесс API/worker и один локальный файл SQLite. Не запускайте несколько реплик с общей базой. Для большого SaaS потребуются отдельные workers, распределённая блокировка устройств и серверная БД.
- Один активный QR на компанию. До завершения/сверки QR устройство резервируется. Это влияет на пропускную способность.
- Банковская сессия хранится на диске Android/AVD. AES-GCM в БД защищает телефон, webhook-секрет и привязку устройства, **не весь диск Android**. Для него нужно шифрование диска хоста.
- В кабинете один общий операторский доступ. Раздельные кабинеты клиентов, роли, MFA и биллинг SaaS ещё не реализованы.
- Возвраты, отмена банковского счёта и автоматическое разрешение неопределённой операции без идентификатора не реализованы.
- APK, эмулятор, Java и Android SDK устанавливаются отдельно. Docker-образ содержит API, а не готовую Android-ферму.
