# Изолированное развёртывание рядом с MTaxi

Статус: шаблоны подготовлены, на удалённом сервере не выполнялись.
SSH к предоставленному адресу на порту 22 отклоняет подключение. До доступа
невозможно подтвердить ОС, занятые порты, домен, свободную память и текущую схему MTaxi.

## Обязательная предварительная проверка (только чтение)

- ОС и архитектура; версии Node/Nginx и способ запуска MTaxi.
- Занятые порты через `ss -ltnp`, ресурсы через `free -h` / `df -h`.
- Состояние текущего MTaxi до любых действий, без чтения его секретов и баз.
- Нет ли чужих файлов/сервисов/пользователя с именем mbusiness. Не перезаписывать.
- Отдельный домен/поддомен и действующий TLS-сертификат для него.

## Предлагаемая изоляция

- Пользователь и группа `mbusiness`, без доступа к каталогам MTaxi.
- Каталог `/srv/mbusiness/`: только MBusiness.
- `/srv/mbusiness/releases/RELEASE/`: исходники и собственный node_modules.
- `/srv/mbusiness/current`: ссылка только на свой release.
- `/srv/mbusiness/runtime/`: отдельный Node.js >=24. Не менять системный Node,
  глобальные npm-пакеты, PM2, Docker или runtime MTaxi. Артефакт Node скачивать
  из официального источника и проверять по официальному SHA256.
- `/srv/mbusiness/shared/.env`: независимые ADMIN_PASSWORD и ENCRYPTION_KEY, 0600.
- `/srv/mbusiness/shared/data/cashier.sqlite`: отдельная новая база. Не переносить
  локальные тестовые данные и не обращаться к базе MTaxi.
- Отдельная unit `mbusiness.service`; только её можно запускать/перезапускать.
- Первоначальный backend `127.0.0.1:3181`, после проверки, что порт свободен.
- Для строгой независимости: собственный процесс reverse proxy на свободном
  HTTPS-порту, например 8443, с собственными PID/config/logs/сертификатом.
  Это позволяет обойтись без изменения и reload общего Nginx MTaxi.
- Отдельные ссылки вида `https://ОТДЕЛЬНЫЙ_ДОМЕН:8443/`, `/docs`, `/operator`.
  Адрес и порт до проверки DNS и firewall не считаются готовыми.

Шаблон systemd: `ops/mbusiness.service`. Он ограничивает CPU/память MBusiness;
требует существующего runtime и каталогов. Шаблон отдельного proxy-процесса:
`ops/mbusiness-nginx.conf.example`, не включать в конфигурацию MTaxi.
На одном физическом сервере ресурсы всё равно общие; отдельные каталоги и
ограничения не создают отдельную виртуальную машину.

## Конфигурация нового сервиса

Из отдельного release выполнить `npm ci --omit=dev` своим runtime. Не использовать
глобальные пакеты MTaxi. Сгенерировать новые локальные секреты без вывода в журнал.
Задать в `/srv/mbusiness/shared/.env`:

```
NODE_ENV=production
HOST=127.0.0.1
PORT=3181
PUBLIC_BASE_URL=https://ОТДЕЛЬНЫЙ_ДОМЕН:8443
DATA_DIR=/srv/mbusiness/shared/data
DRIVER_MODE=kaspi
LIVE_AUTOMATION_ENABLED=false
TRUSTED_PROXY_IPS=127.0.0.1
WEBHOOK_ALLOWED_ORIGINS=
```

Добавить случайные ADMIN_PASSWORD (минимум 24 символа) и ENCRYPTION_KEY
(base64 от 32 случайных байтов) непосредственно на сервере в файл 0600.
Не использовать приведённые шаблоны как реальные значения, не печатать их.
Все будущие компании должны привязать собственные API-ключи к своему
исходящему публичному IP. Привязка IP MBusiness-сервера не заменяет их привязки.

Проверки: backend health, сертификат и HTTPS, вход/регистрация, IP-привязка,
пополнение и подписка с фиктивной компанией, после этого очистить только свои
тестовые данные. Реальная банковская авторизация и платёж требуют отдельной
контролируемой проверки; до неё реальные операции остаются выключенными.

## Что не делать

Не редактировать/restart/reload MTaxi, его PM2/Docker/systemd и веб-сайты.
Не занимать его порты, не менять его DNS, env, Node или базу.
Не выполнять глобальные обновления ОС/пакетов и не заменять firewall целиком.
Для нового внешнего порта добавляется только точное правило после проверки,
без изменения правил MTaxi. Любой конфликт решается выбором другого собственного
порта/каталога, а не остановкой существующего приложения.

## Откат

Останавливать только mbusiness.service и собственный proxy-процесс. Переключать
только `/srv/mbusiness/current` на предыдущий собственный release, сохраняя
базу и ENCRYPTION_KEY. Не применять команды остановки по широким именам процессов.
